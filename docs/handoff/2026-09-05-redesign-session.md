10. **Removed `framer-motion`**, consolidated on the `motion` package (which phosphor-animated's icons depend on) to avoid two animation-library instances in the tree. `theme-toggle.tsx` now imports `motion/react` instead of `framer-motion`.
11. **Two rounds of hover-animation bugs**, both fixed the same way: the animated icons' own built-in `trigger="hover"` listener (native mouseenter/mouseleave on the SVG itself) didn't reliably fire when the icon was hovered — this was reported first for the row arrow icon (fixed: row-wide hover now drives it), then again for the theme-toggle's sun/moon (fixed identically). Fix pattern: set `trigger="none"` on the icon, hold a `ref<AnimatedIconHandle>`, and call `ref.current.play()`/`.stop()` from the *ancestor's* real `onMouseEnter`/`onMouseLeave` instead of relying on the icon's own listener.
12. Also removed the redundant CSS `translate-x`/`translate-y` hover-nudge on the row arrow, since the icon's own animation now covers that (kept the `group-hover:text-primary` color change). *(Superseded in session 2 — see below.)*

## Session 2 — cleanup and composition: what changed

1. **All the dead code flagged in session 1 was removed**, after grepping each for references: `src/lib/icon-context.tsx`, `src/lib/icon-map.tsx`, `src/lib/shape-context.tsx`, `src/lib/font-weight.ts`, `src/components/ui/separator.tsx`, plus four unused tracked assets (`hero.png`, `react.svg`, `vite.svg`, `public/icons.svg`). The icon abstraction was the big one: `IconProvider` was never mounted, so `useIcon` always hit its fallback, and the ~50-entry map was pulling ~46 unused Phosphor components into the bundle. The four icons actually used are now imported directly in `intro-section.tsx`. **JS went 514 kB → 382 kB.**
2. **The intro entrance animation was half-broken and nobody noticed.** The CSS selector was `[data-intro] > *`, which only matches *direct* children — but `--i` was set on the `h1`, `p`, and contact row, which sit one level deeper inside the grid wrapper. Only the wrapper and the photo ever animated. Switched to a per-element `[data-intro-item]` marker so all four beats (0 / 1 / 2, photo at 1) actually fire. The wrapper deliberately does *not* animate, or its transform would compound with its children's.
3. **Components split into named pieces** (the guiding idea: name the concept, don't just shrink the file). New: `ListSection` (section + heading + `divide-y` list, takes rows as children), `FlipPhoto`, `SiteFooter`, and a `useIconHover` hook that captures the session-1 ref pattern in one place. `IntroSection` now reads as `<Headline /> <Bio /> <ContactLinks /> <ProfilePhoto />`. `ThemeToggle`'s motion config moved into a local `IconSwap`.
4. **Separator elements replaced by `divide-y divide-border`** on the list container — deleted the `Fragment` + `index > 0 && <Separator />` dance from both list files and the `Separator` component with it.
5. **Design tokens cut from 111 to 35.** Removed the shadcn starter set nothing referenced: `--sidebar-*` (8), `--chart-1..5`, `--popover`, `--accent`, `--font-heading`, dead spinner keyframes, then `--secondary`/`--destructive`/`--input`/`*-foreground` once the button stopped needing them. Verified after each cut that every `var()` in the built CSS still resolves.
6. **`Button` reduced to one fixed appearance** — no `variant`, no `size`, no `className` (omitted from its props type, so restyling from a call site is a compile error). Removed `class-variance-authority` as a dependency. Styling moved to `src/components/ui/button.module.css`: plain CSS with native nesting, reading the same tokens from `index.css`. Consequence: the theme toggle grew 28px → 36px to match the contact icons. The user explicitly accepted departing from the shadcn primitive here.
7. **Added a `page-width` utility** (`@utility` in `index.css`) replacing `mx-auto max-w-5xl px-6` in three places.
8. **Two real bugs fixed in passing.** (a) A Base UI console error — the contact icons render as `<a>` through `Button`'s `render` prop, which needs `nativeButton={false}`. (b) The shadcn base class carried `[&_svg:not([class*='size-'])]:size-4`, which forced *every* icon to 16px via CSS and silently overrode the `size` prop — contact icons asked for 20px and rendered at 16px. The override is gone; the prop is now the only source of truth.
9. **`oxlint` now ignores `.claude/**` and `.agents/**`** — it was reporting 15 warnings from a bundled skill script. `.agents` is a separate directory with the same content, so both were needed.

**Net:** CSS 45.86 kB → 36.52 kB, JS 514 kB → 382 kB, `index.css` 208 → ~118 lines, `button.tsx` 58 → 9 lines.

## Preferences learned (saved to project memory)

- **Don't use the claude-in-chrome browser tool** to verify UI changes — make the change, typecheck, report what is and isn't verified, and let the user check visually. Automated hover-based verification produced inconsistent results in session 1 even for interactions later confirmed working.
  - **This got missed at the start of session 2 and the user had to repeat it** ("I've told you this before"). Root cause: session 1 saved it to `~/.claude/projects/-Users-jeremywalton/memory/` — the *home-directory* project scope — but a session started in this repo only loads `~/.claude/projects/-Users-jeremywalton-Workspace-jeremy-walton-github-io/memory/`, which was empty. It is now saved in the repo's scope as `feedback-no-chrome-automation.md`. **Lesson for future sessions: save repo-specific preferences to the repo's own project scope, not the home one.**
- **Prefers deletion over keeping things "just in case"** (`feedback-prefers-deletion.md`): every proposed cut in session 2 was accepted and more were requested, including explicitly accepting a departure from the shadcn primitive "for simplicity." Two things held as exceptions: a scale is not dead code, and a token documented in `DESIGN.md` is a design decision — surface the drift and ask rather than deleting.
- User iterates in tight feedback loops on visual/UX decisions (color, layout, icons) — expect several small follow-up corrections per feature rather than one big upfront spec. Each round in this session was a real, specific complaint ("too similar," "chunky," "tombstone," "not animating") rather than vague dissatisfaction — treat feedback literally and don't re-litigate earlier decisions defensively.
