# Handoff — 2026-09-05 redesign session

Session goal: redesign the site to feel more like una.im's personal-developer site (warmer, less clinical) than the original steel-blue/flat/interfaces.dev-inspired look. Went through several rounds of user feedback. **Working tree is clean — everything below is committed** (latest commit: `405cb0e Add animated icons`). `docs/DESIGN.md` was kept up to date after every change and is the source of truth for current tokens/rules; this doc is a narrative summary, not a replacement for it.

## What changed, roughly in order

1. **Docs reorganized.** `PRODUCT.md`/`DESIGN.md` moved from repo root to `docs/`; `PRD.md`/`TECHNICAL_DESIGN.md` moved from `docs/plans/` to `docs/` (user did this part directly). `AGENTS.md` rewritten to describe these files with progressive disclosure (path + one-line "read when X") instead of `@file` hard links that force them into every context.
2. **Color system rebuilt.** Steel blue → warm terracotta (rejected: user didn't like orange) → deep navy landed on `#1a2a3c` per user's exact hex → that navy was *too close in lightness* to the ink/body-text color in light mode ("Jeremy" and "Walton" read as the same dark gray) → final: `oklch(0.38 0.10 252)` light / `oklch(0.72 0.06 252)` dark, pushed lighter/more chromatic than the literal hex specifically to clear separation from ink. Background also pulled off near-white (`oklch(0.985...)` → `oklch(0.95 0.014 250)`) since it read as too clinical.
3. **Typography:** added Fragment Mono (not IBM Plex Mono/Space Mono — those are the "AI reflex" defaults per the impeccable skill's font ban list) for small labels/sources/numerals only. Libre Baskerville still name-only, Karla still body/headings.
4. **Layout rebuilt from a single centered column into full-width alternating bands** (hero / work / footer), each with `mx-auto max-w-5xl` inner container. Hero went from stacked-centered text to an asymmetric two-column grid. Projects + Reading List went from stacked full-width sections to a side-by-side asymmetric grid in one "Work" band.
5. **Hero graphic went through two designs:** first a CSS-only arch-shaped monogram ("JW") standing in for a missing photo — user later called this a "tombstone" and had a real photo (`src/assets/profile-min.png`) they wanted used instead. Rebuilt hero photo as: one source image, CSS `grayscale`/`dark:grayscale-0` for the light/dark B&W-vs-color look (deleted the separately-exported `profile-min-bw.png` — the filter reproduced it closely enough), then added a 3D flip-card hover effect (reference: the AbubakerSaeed CodePen) showing the *opposite* rendering on the back face regardless of theme. Flip duration tuned from 700ms → 1000ms per feedback.
6. **Section headings renamed** "Projects"/"Reading List" → "What I'm working on"/"What I'm reading" (first-person, matches brand voice). Went through a filled/outlined chip-box treatment first — user called it "chunky"/"ugly" — replaced with plain text: one heading in navy, the other in ink with a navy underline. Two quiet, distinct treatments, no boxes.
7. **Reading list category badges (UI/AI/CSS/Rails) removed entirely** — user said they weren't helpful. Deleted the dead `Badge` component (`src/components/ui/badge.tsx`) and the `Category` type/field once nothing referenced them (verified via grep before deleting). Built one shared `ListRow` component (`src/components/list-row.tsx`) used by both Projects and Reading List, so the two lists can't visually drift apart again. Row anatomy: title + optional inline source (mono, same line, wraps together) + arrow icon right-aligned, optional description/note below. Added `source` to the three Projects entries (`rolemodelsoftware.com/optics`, `/home-tab`, `/life-context`).
8. **Footer added:** plain, not sticky — "©2026 Jeremy Walton" left, a "Proverbs 3:5-6" link (to bible.com) right.
9. **Icons swapped to [phosphor-animated.com](https://phosphor-animated.com/)** (shadcn-registry-installed source files under `src/components/icons/`, MIT) for sun, moon, envelope, and arrow-square-out (closest match to the old plain arrow-up-right glyph — phosphor-animated doesn't have that exact one). GitHub/LinkedIn/X **stay on plain `@phosphor-icons/react`** — phosphor-animated has no brand logos, confirmed by curling the registry (`/r/github.json` etc. all 404).
10. **Removed `framer-motion`**, consolidated on the `motion` package (which phosphor-animated's icons depend on) to avoid two animation-library instances in the tree. `theme-toggle.tsx` now imports `motion/react` instead of `framer-motion`.
11. **Two rounds of hover-animation bugs**, both fixed the same way: the animated icons' own built-in `trigger="hover"` listener (native mouseenter/mouseleave on the SVG itself) didn't reliably fire when the icon was hovered — this was reported first for the row arrow icon (fixed: row-wide hover now drives it), then again for the theme-toggle's sun/moon (fixed identically). Fix pattern: set `trigger="none"` on the icon, hold a `ref<AnimatedIconHandle>`, and call `ref.current.play()`/`.stop()` from the *ancestor's* real `onMouseEnter`/`onMouseLeave` instead of relying on the icon's own listener.
12. Also removed the redundant CSS `translate-x`/`translate-y` hover-nudge on the row arrow, since the icon's own animation now covers that (kept the `group-hover:text-primary` color change).

## Incomplete / open items

- **Root cause of the native-hover-not-firing bug was never actually isolated.** We worked around it twice (ref-driven `play()`/`stop()` instead of the icon's own listener) rather than diagnosing *why* `trigger="hover"` fails inside a `Button`/`AnimatePresence` wrapper (and, per the user's second report, even in a plain row context at first). If a *new* animated icon is added anywhere and relies on its own hover trigger rather than the ref pattern, expect it to silently not animate — use the ref pattern from the start.
- **The last two fixes (row-hover-drives-icon, theme-toggle ref fix) have not been visually confirmed by the user yet** — I was asked to stop using the browser tool mid-session, so verification is pending on their end.
- **Dead code flagged but not removed** (out of scope each time it came up, left for a future pass if wanted):
  - `src/lib/icon-context.tsx`'s `IconProvider`/multi-library-switcher (press "i" to cycle icon libraries) is never mounted anywhere — 100% dead scaffolding, likely leftover from a starter template. Only one library ("phosphor") has ever existed.
  - `src/lib/shape-context.tsx` (`ShapeProvider`/`useShape`) has no consumers left after the Badge component was deleted — also dead.
  - `~40` of the ~50 `IconName` entries in `src/lib/icon-map.tsx` are unused by any component (only sun/moon/envelope-simple/arrow-up-right/github/linkedin/x-logo are actually referenced). Left alone since they don't break the build and trimming them wasn't asked for.
- **`docs/DESIGN.md`'s "Tag Article/Guide/Repo" color tokens were removed** when badges were deleted, but the `--card`/`--surface` neutral ramp and general system are otherwise current and trustworthy.
- **impeccable skill has an update available** (installed v3.9.1 → latest v4.2.0). User was asked once early in the session and it was never explicitly accepted or declined — still pending, non-blocking.

## Preferences learned this session (saved to memory)

- **Global** (`~/.claude/projects/-Users-jeremywalton/memory/no-browser-verification.md`): don't use the claude-in-chrome browser tool to verify UI changes — make the change, typecheck, report done, and let the user verify visually themselves. Automated hover-based verification in this session produced inconsistent/untrustworthy results even for interactions later confirmed to work.
- User iterates in tight feedback loops on visual/UX decisions (color, layout, icons) — expect several small follow-up corrections per feature rather than one big upfront spec. Each round in this session was a real, specific complaint ("too similar," "chunky," "tombstone," "not animating") rather than vague dissatisfaction — treat feedback literally and don't re-litigate earlier decisions defensively.
